# Контракты данных и результатов — версия 1.1

Имена столбцов — в [schemas/columns.json](../schemas/columns.json). CSV: UTF-8, разделитель запятая, десятичная точка, без разделителей тысяч. Пустое поле означает допустимое отсутствие значения; строки `NaN`, `Inf`, `null` в числовом CSV недопустимы. Идентификаторы регистрозависимы и уникальны в своей таблице. Дополнительные столбцы разрешены, обязательные не переименовывают.

`sample_submission.csv` и [examples/empty_submission](../examples/empty_submission) содержат заголовки без решений. Их нужно заполнить собственными результатами. Пустой комплект не является успешно выполненным кейсом.

## Входы

`events.csv`: `event_id,region_id,date,split`. Дата — ISO 8601; split: `train`, `validation`, `test`.

`chips.csv`: `chip_id,event_id,scene_id,aoi_id,s1_path,s2_path,label_path,valid_mask_path`. Пути относительно корня набора. Отсутствующий S2 — пустой путь; test label всегда пуст. Для конкурсного релиза добавляются даты наблюдения, каналы, CRS, transform, размеры, источники и хеши в манифесте. Каждый дочерний фрагмент имеет исходную сцену; идентификатор события не заменяется именем случайного файла.

`aoi.csv`: `aoi_id,reference_raster,split`. Эталонная сетка — одноканальный GeoTIFF, маска которого задает допустимую область прогнозирования из разрешенных входов, без использования скрытой целевой разметки. Именно с этой сеткой сравнивает выходы валидатор. Для каждой тестовой AOI нужен результат. В учебных таблицах пути пусты, потому что растр не выдан.

`exposure.csv`: одна строка на единицу учета. Обязательны `asset_id,aoi_id,asset_class,asset_value_rub,vulnerability_coef,value_date,value_basis`. V ≥ 0; q ∈ [0,1]. В demo дополнительное поле `chip_id` связывает все 10 объектов с `DEMO_CHIP3`. Геометрия — по `asset_id` в `assets.geojson` (WGS84); дополнительные координаты точек допустимы. Площадные части одного актива могут стать отдельными единицами с распределенной стоимостью и `parent_asset_id`. Родитель не включается повторно в сумму. Если выдаются доли, их нормировку проверяет организатор.

`pricing_tiles.csv`:

| Поля | Формат и смысл |
|---|---|
| `candidate_id`, `area_km2` | Уникальная позиция и оплачиваемая площадь ≥ 1 км² по контуру; минимум до округления, точность 0,001 км² |
| `sensor_type`, `resolution_m` | `optical` / `sar`; разрешение > 0 м |
| `acquisition_type`, `acquired_date` | `new` / `operational` / `archive`; для имеющихся данных дата YYYY-MM-DD |
| `guaranteed_purchase`, `available_at` | `true` / `false`; ожидаемая доступность с часовым поясом |
| `processing_level`, `usage_mode` | `L0/L1/L2`; `internal/limited/unrestricted` |
| `data_role` | `event_observation` / `context`; пригодность для события подтверждена организатором |
| `base_rate_rub_km2`, `base_rate_status`, `base_rate_source` | Б ≥ 0; `scenario/official`; источник конкретной ставки |
| `zero_rate_basis` | Обязателен при Б = 0 |
| `discount_group_id` | Ключ заранее заданной однородной группы скидки |

Геометрии кандидатных зон — в `candidates.geojson`: один `Polygon` на `candidate_id`, без holes и самопересечений. Произвольная ломаная форма разрешена. Площадь в `area_km2` сверяется с контуром по [единому протоколу](ORDER_GEOMETRY.md). Каталог конкурса дополнительно содержит фактические даты наблюдения/ожидаемую дату новой съемки и признаки качества. `available_at` — срок доступа к продукту, а не обязательно момент наблюдения. Конкурсный каталог должен отделять эти понятия. В demo связи покрытия получены по синтетическим контурам и точкам; они воспроизводимы геометрически, но не описывают реальное событие.

`candidate_units.csv`: `candidate_id,unit_id`. `unit_id` соответствует `asset_id` в контрольном портфеле. Одна пара встречается один раз. Для context-позиций связь может обозначать контекст, но не добавляет покрытие текущего ущерба. Таблица готовится организатором; изменение связей требует проверки геометрии и пригодности наблюдения.

`config.json`: редакция, дата цены, deadline с часовым поясом, бюджет, профиль пользователя, группы скидок с типом/разрешением, календарным годом и предыдущей площадью. `order_geometry` фиксирует `type=Polygon`, `allow_holes=false`, `min_area_km2=1.000`, `area_crs=EPSG:6933` и правило покрытия `point_covers` для точек либо `organizer_verified_units` для подготовленных площадных единиц. Бюджет контроля относится к **цене заказанных данных**. Если команда рассматривает ограничение полной стоимости решения, она добавляет его отдельным сценарием.

## Растры

| Выход | Требование |
|---|---|
| `flood_probability.tif` | Один канал Float32, p ∈ [0,1], nodata = −9999 |
| `flood_mask.tif` | Один канал UInt8, 0/1, nodata = 255 |
| `raster_manifest.csv` | `aoi_id,probability_path,mask_path`; одна строка на тестовую AOI |

CRS, transform, размер и valid mask совпадают с выданной опорной сеткой. Бинарный выход равен `p >= threshold`, где threshold зафиксирован по validation в метаданных. Если требуется иная постобработка, сохраните ее отдельным дополнительным продуктом; контрольная маска остается воспроизводимой из вероятности. Для одной AOI файлы лежат в корне, для нескольких — например `rasters/AOI_ID/flood_probability.tif`. Объединять разные CRS в один некорректный растр нельзя. Валидационные метрики считаются только там, где есть валидная целевая метка, даже если допустимая область inference шире.

## Объекты: `asset_loss.csv`

| Поле | Правило |
|---|---|
| `asset_id`, `aoi_id` | Совпадают с фиксированным портфелем |
| `p_flood` | Для точки — вероятность; для площадной единицы — объявленная ожидаемая доля; [0,1] |
| `expected_loss_rub` | Ожидаемый прямой ущерб в рублях; по умолчанию pVq, округление до копеек |
| `uncertainty` | Неотрицательный показатель с методом и единицами в метаданных |
| `rank` | 1…N для оцененных объектов, по убыванию заявленного EL; порядок равных значений свободен |
| `coverage_fraction` | Доля доступной опоры объекта в [0,1] |
| `status` | `ok` при покрытии 1; `partial` при 0 < покрытие < 1; `no_data` при 0 |

При `partial/no_data` базовые p, EL и rank пусты. Дополнительный прогноз по наблюдаемой части допустим в других полях. Для `ok` uncertainty обязателен; для неизвестных объектов может отсутствовать. Одна строка на каждый актив, включая неоцененные. В demo это 10 строк, а не четыре. Дополнительные интервалы должны содержать уровень, метод и указание, интервал какой величины показан.

## Заказ: `procurement_plan.csv`

Одна строка на выбранную позицию. Пустой заказ допустим и содержит только заголовок. Поля цены включают исходную площадь и Б, статус Б, О/П/Т/Р, группу и общую площадь для скидки, цену за км², стоимость, формулу и редакцию. Порядок полей и канонический формат строк дает `pp840_helper.PRICE_FIELDS`. Проще экспортировать строки, которые вернула функция `price_plan`, сохранив решение выбора отдельно. Валидатор требует точное совпадение этих строк с повторным расчетом и сумму в пределах бюджета.

## Экономика

`strategy_plans.json`: объект с ключами A/B/C и массивами candidate_id; A пуст, C совпадает с планом заказа. B формируется по объявленному правилу широкой закупки.

`strategy_comparison.csv`: одна строка A/B/C. `data_cost_rub` — общий модуль цены; `other_cost_rub` — остальные раскрытые статьи; `decision_cost_rub` — их сумма; `budget_feasible` — true/false по бюджету данных. `covered_expected_loss_rub` — уникальное пригодное покрытие оцененного EL; `coverage_share` — доля в оцененном EL, пуста при нулевом знаменателе. `residual_uncertainty` имеет общие для трех стратегий метод и единицы; `uncertainty_status` = `measured/scenario/not_estimated`; `uncertainty_basis` объясняет источник или отсутствие оценки. При `not_estimated` число пусто. Такой статус технически допустим, но сам по себе не выполняет критерий сравнения остаточной неопределенности.

`sensitivity.csv`: по строке на вариант стратегии и измененных входов. `scenario_id` уникален; `changed_inputs_json` — JSON-объект с изменениями; далее итоговая стоимость решения, покрытый EL, статус measured/scenario и интерпретация. Диапазоны и сценарии выбирает команда. Формат не задает желательный результат.

`run_metadata.json`: версия данных, commit кода, seed, версии среды, threshold, метод uncertainty, агрегация, правило B, описание затрат и статусов сравнения, действие пользователя, оцененный EL и неоцененная стоимость активов. Добавьте время отдельных этапов, источник весов, лицензии, показатели по событиям, численную погрешность и ссылки на карту/презентацию.

## Проверка

```bash
python -m tools.validate_submission --data data/competition --submission outputs/team
```

`--tables-only` выполняет неполную проверку без GeoTIFF, но с обязательной проверкой геометрий заказов; для нее также нужны зависимости из `requirements.txt`. Ее успех нельзя назвать полной приемкой. Автоматическая проверка формата не заменяет проверку пространственной агрегации, целевой метки и научного вывода.

### Альтернативная экономическая модель

По умолчанию `loss_model=control_pvq`: модуль проверяет формулу pVq. Для разрешенного критерием 11 другого подхода задайте `loss_model=declared_custom` и непустой `loss_model_reference` со ссылкой на метод и воспроизводимый код команды. Тогда модуль проверяет числовые значения, состав портфеля, ранги, суммы, покрытие и цену, но возвращает `loss_formula_checked=false`. Содержательная проверка альтернативной формулы выполняется отдельно; это не освобождение от обоснования ущерба.
