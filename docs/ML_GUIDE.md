# Подготовка к обучению и работе с вероятностями

Выбирайте подход по доступной разметке, вычислениям и проверяемой гипотезе. Небольшая модель, которая сохраняет качество на новом событии и дает понятный заказ, может оказаться полезнее тяжелой сети с хорошим результатом на соседних фрагментах.

## Три входа в задачу

| Подготовка | С чего начать | Что исследовать дальше |
|---|---|---|
| Python есть, опыта ML мало | Вводный ноутбук, чтение GeoTIFF, визуальная проверка каналов; объяснимый порог или простая модель | Вероятностное отображение, проверка ложных тревог, стабильность на другом событии |
| Есть опыт классификации | Признаки S1/S2, пространственный split, классификатор пикселей или компактная сеть | Контекст соседей, дисбаланс, калибровка, работа без S2 |
| Есть опыт сегментации | U-Net/DeepLab/SegFormer с контролем данных и памяти | Перенос по событиям, ансамбли, абляции, надежность и экономическая ценность |

Это маршруты подготовки, а не уровни баллов. Общие критерии одинаковы.

## Один осмысленный цикл обучения

1. Проверьте один фрагмент: каналы, шкалу, nodata, совмещение маски, постоянную воду и дату. Затем подтвердите те же свойства автоматически для набора.
2. Загрузчик должен возвращать признаки, целевую маску, valid mask и идентификаторы события/сцены. Неизвестные пиксели исключаются из функции потерь и метрик.
3. Зафиксируйте split. Все производные окна, аугментации и статистики связаны с родительскими данными. Статистики каналов вычисляются на train.
4. Запустите маленький технический эксперимент, чтобы проверить формы тензоров и градиенты. Способность запомнить несколько обучающих фрагментов проверяет проводку кода, но не качество переноса.
5. Обучите простой ориентир и основной подход. Для дисбаланса обсуждайте функцию потерь и выборку; общая accuracy при преобладании суши малоинформативна.
6. Выберите checkpoint, порог и калибровку по validation. При многократном подборе разделите validation на настройку и калибровку либо примените вложенную схему по событиям; опишите ограниченность выборки.
7. Заморозьте конфигурацию до test. Выполните inference по всей требуемой территории, соберите мозаику с сохранением сетки и nodata. Края перекрывающихся окон не должны создавать двойной учет.
8. Передайте вероятности в экономическую часть; сравните изменения карты, ущерба и заказа. Положительная разница IoU не гарантирует лучшую закупку.

Порог и калибровку нельзя выбирать по скрытой проверке. Извлечение маски валидности из скрытых меток тоже раскрывает информацию. Для inference маска допустимой области получается из разрешенных входов.

## Вероятности и неопределенность

Sigmoid или softmax обеспечивают диапазон, но не калибровку. Reliability diagram для бинарной целевой воды сравнивает среднее p с фактической долей затопленных пикселей в интервале. Сохраните границы интервалов и число наблюдений. Brier score показывает квадратичную ошибку вероятностей; его полезно читать вместе с частотой класса и калибровкой по событиям. ECE зависит от биннинга и не заменяет весь анализ. [Guo et al., 2017](https://proceedings.mlr.press/v70/guo17a.html).

Ансамбль может оценивать разброс предсказаний, но одинаково ошибающиеся модели дадут малый разброс. Сопоставляйте неопределенность с частотой ошибок, анализируйте уверенные ошибки и перенос. Не называйте любое стандартное отклонение «95%-м доверительным интервалом». [Lakshminarayanan et al., 2017](https://arxiv.org/abs/1612.01474).

## Ресурсы и воспроизводимость

Начните с CPU-проверки чтения и одного batch. Уменьшайте batch size, число каналов или размер модели при нехватке памяти; mixed precision используйте с проверкой стабильности. Сохраните seed, версии, конфигурацию, статистики нормализации, веса, порог, калибратор и журнал качества по событиям. Для GPU заранее укажите допустимую численную погрешность; один seed не гарантирует побитовое совпадение всех операций.

Бесплатный Colab не гарантирует GPU, длительность сессии или конкретный объем памяти. Нужны короткая проверка запуска и отдельный воспроизводимый путь inference по сохраненным весам. Не скачивайте многогигабайтный набор при каждом пересчете бюджета. Не храните снимки, веса и закрытые метки в Git.

## Вопросы для самостоятельного исследования

Что происходит без S2? Где S1 дает уверенную ошибку? Меняется ли приоритет дорогих активов после калибровки? Сохраняется ли преимущество модели на другом событии? Стоит ли ждать более точный снимок, если решение требуется раньше? Какую часть ошибки ущерба определяет q, а какую — модель воды?

Ответы на эти вопросы должны следовать из вашего эксперимента. Готового набора гиперпараметров, обученной модели и алгоритма оптимального заказа здесь нет.
