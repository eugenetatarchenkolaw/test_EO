# Вероятность, ущерб и сравнение стратегий

Экономический расчет относится к одному событию и десяти учебным точечным объектам. Он не является годовым ожидаемым ущербом, страховой выплатой или официальной оценкой имущества. Общие научные основания и ограничения оценки паводкового ущерба рассматривают [Merz et al.](https://nhess.copernicus.org/articles/10/1697/2010/).

## Обязательный расчет

Для каждого из десяти объектов постановка задает:

$$
EL_i = p_i V_i q_i.
$$

p извлекается из исходного `flood_probability.tif` основного метода в координате объекта. V и q берутся из [фиксированной таблицы](DATA.md#фиксированные-типы-объектов). q — учебная доля прямого ущерба при затоплении, не еще одна вероятность.

**Порог бинаризации не обнуляет ущерб:** при p ниже порога объект остается в расчете pVq. Сохраните правило извлечения p и код вычисления. Другие модели допустимы как дополнительные эксперименты и не заменяют обязательную.

Для `ok` укажите p и EL. Если оценка отсутствует или ненадежна, раскройте `partial/no_data`, оставьте неоцененные p/EL/rank пустыми и отдельно покажите неоцененную экспозицию. Приоритет `rank` в обязательном файле определяется по убыванию EL; при равенстве — по asset_id. Дополнительные приоритеты по неопределенности или значимости объекта объясняются отдельно.

Проверьте связь неопределенности с ошибками и ее перенос к объектам. Равенство высокой уверенности и высокой надежности нельзя предполагать без проверки. Учебные V/q и вероятность воды не сообщают глубину затопления; функции [JRC](https://publications.jrc.ec.europa.eu/repository/handle/JRC105688) служат научным контекстом, а не заменой таблицы кейса.

Прокси-проверка pVq против yVq выполняется на независимых ручных метках с зафиксированными V/q; порядок и ограничения описаны в [протоколе проверки](VALIDATION.md#прокси-проверка-ущерба).

## A/B/C — три стратегии заказа

| Стратегия | Содержание |
|---|---|
| A | Только открытые данные, без платной съемки |
| B | Широкая закупка по заранее объявленному правилу команды |
| C | Выборочная закупка по приоритетам модели в пределах бюджета платных данных |

Для всех трех используются один S1-чип, одна исходная карта вероятностей основного метода, тот же портфель, момент решения и правила цены. B/C используют один авторский каталог. Отдельные A/B/C по baseline не обязательны.

В `strategy_comparison.csv` стоимость решения равна сумме стоимости данных и отдельно раскрытых прочих затрат. Объявленный `budget_rub` ограничивает стоимость платных данных. B сверх бюджета обозначается как контрфактическая. C должна соблюдать лимит; пустая корзина допустима при отсутствии подходящих заказов.

`covered_expected_loss_rub` — EL уникальных оцененных объектов в пригодных, доступных к сроку зонах текущего наблюдения. `coverage_share` — его доля в суммарном оцененном EL; при нулевом знаменателе поле пустое с объяснением. Повторное покрытие не увеличивает EL, контекстный архив не становится наблюдением текущей воды.

Для A сохраняется исходная неопределенность со статусом `baseline`. Для B/C без новых наблюдений нельзя автоматически объявлять снижение: сценарная оценка имеет статус `scenario` и раскрытую формулу, реально проверенная — `measured`, отсутствие оценки — `not_estimated` с пустым числовым полем. Единицы, агрегация и основания раскрываются в паспорте запуска.

Покупка данных меняет доступную информацию. Чтобы утверждать снижение реальных потерь, нужны действие и подтверждение эффекта. Покрытый EL сам по себе не является экономией или предотвращенным ущербом.

## Чувствительность

Проверьте ущерб при изменении **p, V и q по отдельности**, фиксируя остальные параметры. Сценарные p остаются в [0,1]; правило изменения раскрывается. Эти эксперименты не меняют фиксированные V/q обязательного исходного портфеля.

Отдельно проверьте план закупки как минимум при изменении **бюджета и одного экономического параметра**, например ставки. Сохраните состав корзины, стоимость, уникально покрытый EL, статус неопределенности и интерпретацию. Диапазоны и сценарии выбирает команда; обязательных процентов изменения нет.

Смена только бинарного порога не меняет pVq. Значимость социального объекта может влиять на дополнительное ограничение или приоритет, но произвольный множитель важности не следует скрывать внутри прямого рублевого ущерба.
